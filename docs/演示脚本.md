# 演示脚本

> 控场：5 号 · 前端操作：1 号 · 服务与数据：2/3/4 号  
> 前端目标：3 分钟内稳定展示「审计冲突 → 用户裁决 → 校验弃答 → 黑板留痕」。

## 1. 演示前检查

1. 使用 Chrome 或 Edge，窗口宽度建议不低于 1280px。
2. Mock 演示：

```bash
cd frontend
npm install
npm run dev
```

访问：

```text
http://localhost:5173/?demo=1
```

3. 联调演示：将 `frontend/.env` 中的 `VITE_USE_MOCK` 设为 `false`，确认 backend `8000` 健康、Agent `8001` 可用。
4. 页面顶部出现「Mock 模式」或「API 模式」；底部出现「3 分钟必演路径」控制条。
5. 点击「重置」恢复初始状态。

## 2. 三分钟操作路径

### 00:00–00:25 · 双场景与计划入口

1. 首页展示「期末复习 / 跟课补漏」与考试日期、章节、每日分钟、科目。
2. 保持「期末复习、高等数学、45 分钟」。
3. 点击「生成并审计计划」。

预期：进入「学习计划」，显示 `conflict`、硬约束证据和三个用户选项。

### 00:25–00:55 · 审计冲突与用户裁决

1. 指出页面文案：「计划没有可行解，系统没有自行修改。」
2. 选择「降低复习深度」。
3. 点击「提交裁决并重排」。
4. 展示绿色状态「已裁决 · 二次审计通过」，并指出黑板 item 变为 resolved。

预期：计划重排完成；用户选择与证据引用保留。

### 00:55–01:25 · 校验弃答

1. 点击底部演示条「校验弃答」。
2. 页面直接进入「练习中心」，展示黄色 `abstain · 不强行给出答案`。
3. 查看右侧计算检验轨迹：`expand → compare`。

预期：错误草稿不被当作正确答案；页面只给提示与审计轨迹。

### 01:25–01:50 · 共享黑板

1. 打开「共享黑板」。
2. 展示 conflict、challenge、intervention 三类条目。
3. 对一条开放条目点击「处理」。

预期：条目状态由 open 变为 resolved，并保留用户处理记录。

### 01:50–02:20 · 主动干预

1. 点击演示条「时间跳跃」。
2. 自动进入黑板并显示 intervention 条目。
3. 口播：系统基于轨迹主动发起建议，但仍等待用户决定。

### 02:20–02:40 · 学习轨迹

1. 打开「学习轨迹」。
2. 展示作答记录、passed / hint-abstain 数量与掌握度。
3. 口播：错因和求助行为会进入下一轮计划与推荐。

### 02:40–03:00 · 收束

「系统不只生成，它审计、校验、质疑和协商；协作过程在黑板可见，最终裁决权始终在用户。」

## 3. 固定状态

| 动作 | 关键 UI |
|---|---|
| 生成计划 | `planStatus=conflict`，三项 `user_options` |
| 提交裁决 | `planStatus=ok`，conflict entry resolved |
| 校验弃答 | `practice.status=abstain`，`hint_mode=true` |
| 时间跳跃 | intervention entry + 待处理卡片 |
| 完成作答 | attempt 写入 Zustand，轨迹新增记录 |

## 4. 异常与降级

- `agent_unavailable`：保留资料浏览、已存计划与作答记录，并显示明确错误提示。
- 后台不可用：不白屏；页面使用本地已加载状态，黑板同步失败显示 Alert。
- 演示现场建议优先使用 Mock 模式，避免网络与模型波动。

## 5. 冻结约定

- 答辩前只修复演示路径上的阻塞问题，不新增页面。
- 每次修改演示路径后，按本脚本完整走一遍并计时。
- 固定数据来自 `frontend/src/mocks`，不得在演示当天临时改 JSON 字段。

## 6. Agent 侧独立复现

```bash
cd agent
python -m app.demos.run_three_must
python -m app.demos.run_three_must --with-enhancements
```

固定用例见 `agent/examples/`。
